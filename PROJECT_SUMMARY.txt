PROJECT OVERVIEW
Mapping Manager is a cross-platform tooling effort that streamlines configuration, tracking, and communication for MouseHunt mapping runs. The primary deliverable is a Python/Tkinter desktop application (`MappingManager.py`) that allows hunters to curate region/subgroup/enemy hierarchies, manage pricing and completion state, and auto-generate “Looking For” market messages. The project also ships a Tampermonkey userscript (`WebExtension.js`) that mirrors the desktop experience inside the official mousehuntgame.com client, providing a lightweight in-browser control panel for hunters who prefer not to leave the game tab.

CORE PYTHON APPLICATION (`MappingManager.py`)
The Tkinter client encapsulates all runtime logic inside the `MappingManagerApp` class. At startup it builds a multi-pane window: a treeview for hierarchical nodes, context-sensitive controls for editing the selected node, stat summaries, generated market messages, and a todo list. State for each node is stored in nested dictionaries (regions → subgroups → enemies) with properties such as `include`, `needs_snipe`, `completed`, `price`, and optional override text. Undo/redo stacks preserve up to 20 historical states. Persistence is handled through JSON files: users open or create setups, the app auto-saves snapshots, and it remembers the last file path in `~/.mapping_manager/last_file.json`. Utility helpers support deep tree traversal (`deep_find`, `deep_delete`, `preorder_iter`), clipboard copies, price batch adjustments, and UI feedback (status flashes, tooltips). The GUI exposes commands for generating market messages, resetting runs, editing search prefixes, and configuring thank-you messages.

WEB USERSCRIPT (`WebExtension.js`)
This file is a Tampermonkey metadata-wrapped module that injects an overlay into MouseHunt. It recreates the Python app’s layout with DOM elements and plain CSS, storing data via the Greasemonkey value API. Shared concepts—node structure, batch price rules, selection flow, generated message lists—are maintained for functional parity. The script adds browser-specific affordances: clipboard fallbacks, JSON import/export using blob downloads, and menu commands to toggle the panel. Because it runs on the live site, certain desktop features are omitted or simplified, but the naming conventions and state machine mirror the Python implementation so configuration files can be exported/imported across both versions.

ANCILLARY FILES
`main.py` remains the PyCharm-generated stub and can be used as a quick entry point or smoke test but does not contain business logic. The repository assumes contributors maintain an isolated interpreter (`python -m venv .venv`) and keep virtual environment artifacts out of version control. Both the desktop and web apps rely on UTF-8 JSON for configuration exchange.

WORKFLOWS & DATA HANDLING
Contributors typically draft or edit map setups within the desktop tool, leveraging rich editing, undo/redo, and automatic persistence. When needed, they export JSON to share with teammates or load into the web userscript. The generated market message list filters nodes where `include` and `needs_snipe` are true and `completed` is false, sorting by price before name. The todo list focuses on required self-completion tasks. Batch price adjustment steps depend on current price brackets, keeping parity between platforms. The thank-you message and search prefix fields allow quick communication back to hunters or market channels. Manual testing usually consists of running `python MappingManager.py`, loading a sample config, performing node edits, verifying undo/redo, generating messages, and ensuring the JSON persists under `~/.mapping_manager`.

DEVELOPMENT NOTES
There is no build system or external dependency list beyond the Python standard library, Tkinter, and browser script APIs. Future work generally involves refactoring logic into reusable helpers for eventual unit tests (pytest is the suggested framework), extending the userscript UI, or improving integration between desktop and web experiences. Understanding the shared node schema and event flows in `MappingManager.py` and `WebExtension.js` is essential for any new agent stepping into the codebase.
